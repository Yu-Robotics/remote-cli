01 · 代码改完，再请另一种AI检查

让另一种 AI 检查实际交付的修改，再由主助手核实问题和依据，可以多获得一个独立视角。

使用方式

委派已启用且目标后端可用时，要求先完成并整合实现，再交给另一种 AI 审查。

请先委派实现本次修改，结束后显式整合；再请另一种可用的 AI 只读审查整合后的代码，由你核实问题并报告验证结果。

适用范围

审查应基于已整合的修改；Git 助手的修改不会自动合并，审查结论仍需主助手核实。

02 · 多项检查，分别安排助手处理

把互不依赖的检查分别交给助手，再由主助手汇总核实，可以让每项检查都有明确范围和结果。

使用方式

委派可用时，分别说明实现、测试和文档的检查范围，并要求各助手只读返回依据。

请分别委派检查本次实现、测试覆盖和文档一致性，只读不改文件；各自返回问题与依据，由你汇总核实。

适用范围

同一种后端也可用独立会话；复用会话可能保留历史，背景和结论不会自动共享，“只读”是任务要求。

03 · 几项独立修改，同时推进

在 Git 项目中把独立修改交给不同助手，可以按可用执行名额同时推进，再统一整合和验证。

使用方式

明确各项修改互不依赖，要求助手分别在 Git 工作树完成，全部结束后由主助手整合并验证。

请把互不依赖的修改分给不同助手，在各自 Git 工作树中完成；全部结束后显式整合，检查冲突并运行必要测试。

适用范围

Git 按可用名额并发，非 Git 串行；修改需显式整合，不会自动提交或推送。工作树不是系统沙箱。

04 · 为不同分工选择合适的模型

在同一张模型卡中切换配置目标，可以为不同后端保存偏好，而不改变主助手所用后端。

使用方式

任务和队列空闲后发送 /model，先选主后端或其他后端的工作者偏好，再选可用模型并等待确认。

/model

适用范围

设置按当前线程和后端用于后续任务；同后端主助手与工作者共享模型和思考强度，不能逐个独立设置，查看其他目标不切换主后端。

使用方式

原始飞书语音不会被处理，需先听写成文字；安排只影响后续委派，不切换主助手或迁移运行中的任务。

使用方式

确认目标服务还有可用额度及可用后端后，用文字说明后续任务的委派安排。

后续资料检查改用 Kimi，你继续负责整体任务和结果汇总。

适用范围

系统不会自动汇集额度、转移余额或迁移运行中的任务；已安装仍需登录、有可用额度并满足委派条件。

07 · 意见存在分歧时，再核对依据

让主助手整理冲突结论和证据，再安排进一步复核，可以把讨论集中到具体依据上。

使用方式

要求主助手转述分歧、证据和相关代码，再交给可用助手复核，最后逐项验证。

请把两位助手结论冲突的地方、各自依据和相关代码交给另一位可用助手复核，再由你逐项验证并给出结论。

适用范围

主助手显式转述分歧和证据，不是助手之间直接聊天；旧对话和结论不会自动共享，讨论不保证正确。

/effort

10 · 当前任务没结束，先安排下一步

先发送下一项要求并确认入队，可以让它按当前线程的等待顺序接续执行。

使用方式

当前线程忙时发送下一项任务，核对确认卡里的线程和内容，再点 Add to queue；可用 /queue 查看。

完成当前修改后，请检查测试覆盖，并列出仍未覆盖的边界条件。

适用范围

必须明确确认才会入队；未确认或已过期不会执行，队列只存内存，服务重启不保留。

/abort

/compact

18 · 换个项目，先选目录再确认

用目录卡片逐级选择项目，确认后再切换，减少输错路径的麻烦。

使用方式

发送 /cd，点击文件夹进入，或点 ↑ Parent 返回上一级；选好后点 Use this directory，等成功确认再发任务。

/cd

适用范围

只显示允许的目录；浏览不切换。换目录会重置本线程主助手和委派助手对话；文件不删，回原目录也不恢复旧对话；有任务、队列或委派助手在跑时不能应用。

下载 PNG · 可编辑 SVG

19 · 新项目，单独开一个线程

为项目创建有名字的独立线程，各自保留讨论、目录和任务队列。

使用方式

发送 /thread new website；回复新线程的创建卡，再用 /cd 选择项目目录并确认；也可点 + New 创建自动命名线程。

/thread new website

适用范围

新线程沿用原线程目录和后端，不会按名字寻找项目；+ New 创建线程，/new 清理当前线程对话。独立线程不隔离文件权限。

下载 PNG · 可编辑 SVG

21 · 这个线程要不要分工，由你决定

用当前线程的委派开关控制是否允许分工，保留已有讨论。

使用方式

任务和队列空闲后发送 /delegation，在设置卡点 On 或 Off 并等待确认；也可发送 /delegation on 或 /delegation off。

/delegation

适用范围

只影响当前线程，关闭不清历史；开启不立即启动助手，也不保证后端可用。开关不禁用后端自带的原生子助手，沙箱限制仍有效。

22 · 让某种委派助手重新开始

只清理指定后端的委派会话，主助手和其他后端继续保留讨论。

使用方式

等当前线程空闲且委派助手全部结束后，发送 /delegation reset opencode，清理这个线程内所有 OpenCode 委派助手的上下文。

/delegation reset opencode

适用范围

不会重置主助手或其他后端；省略后端名会清理本线程全部委派助手。助手卡的 Clear context 只清卡片对应的一个会话，不撤销文件修改。

24 · 给 Codex 一个持续推进的目标

支持原生目标的 Codex 可以继续推进工作，并保留查看、暂停和恢复入口。

使用方式

使用支持原生目标的 Codex；线程和队列空闲后，先发 /delegation off，再用 /goal 设置目标；/goal 查看状态，/goal pause 暂停，/goal resume 恢复。

/delegation off
/goal --budget 40000 修复失败的测试并保持公开接口兼容

适用范围

预算是正整数token上限，可省略；/goal clear清目标不清对话。中断后需显式恢复，不保证目标完成；附件请先单独发送。

25 · 需要限制命令执行，先查看沙箱

在支持的 Codex 或 Claude Code 线程里，查看并选择原生命令沙箱限制。

使用方式

空闲时先发送 /sandbox 查看状态；需要时用 /sandbox on 或 /sandbox read-only，按当前后端的实际支持设置；/sandbox default 恢复跟随本地配置。

/sandbox
/sandbox read-only

适用范围

不隔离整个AI进程；Claude 的沙箱主要限制 Bash，不支持原生 Windows。/cd 目录白名单是另一项设置；额外授权可能放行越界操作。
